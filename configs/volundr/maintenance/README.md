## Safety and publication

Never install or invoke retired dream hardeners/correction-log rule writers.
No personal notes, identity/security/privacy/access/credential guidance edits,
external consequential actions, unreviewed shared-skill mutations, or automatic pushes.
Lucas's scoped canonical-route task adoption uses explicit reviewed payload records
and preserves every unrelated source edit. It is not published-pin advancement.
A private staged copy is not application. `locally-applied-unpublished` requires
the canonical manifest/review-record gates, full repository tests, pinned dependency
and Gitleaks checks, a local private-clone commit, preserved payload hashes and
recovery receipts. It is not publication, consumer installation/loading or behavior
uplift. No genuine eligible candidate has yet established those downstream outcomes.

Reviewer process receipts bind PID/session IDs, input hashes and private captured
reviewer stdout/verdict hashes. Raw captured reviewer output is private, mode 0400,
never sent in public cron summaries; it is rechecked before consumer writes.
Same-UID process separation is not adversarial isolation. No caller-supplied
`VERIFIED` flag authorizes application. No-change decisions require a separate
source-bound independent review under `run/nochange/`; they never authorize
application. The controller supplies exact-source-token task skills and safely
read source-cited package support, recording every selected path/hash. A denied
no-change is never re-proposed. Only a changed deterministic safe evidence packet
can trigger a distinct `run/nochange-attempt-<hash>/` review, linking its prior
verified denial without modifying it. Identical denied evidence is skipped; two
verified denials exhaust the retry bound even if `seen.json` is lost. Denial
tampering fails closed before any model turn. Proposer choices and candidates
persist across daily allowance pauses without consuming semantic attempts.
Coverage reports extraction-ledger source revisions, not whole-vault completion.

Run existing stdlib unittest suites before each scoped deployment. Qualify the
actual installed script and its output chain before resuming an existing job.
Use supported Hermes cron tools/CLI after inspecting help; never replace the
whole cron store or duplicate jobs. Preserve original overlap `wakeAgent` and
configured agent prompt/delivery semantics. Back up exact named targets and use
base-hash CAS, same-filesystem fsync/atomic replacement, rollback, and hash
readback. Keep old unrelated edits intact.

Task receipts, deployment hashes, rollback copies, model accounting, source
reviews and exact live/staged state are in:
`~/loki-data/live/hermes/cache/scratch/learning-autoapply-20261104/HANDOFF.md`.
Read its current section before adopting a candidate wrapper; historical green

dependency drift fails closed. No runtime dependency install or canonical test skip.

Private-clone application never touches the dirty shared library or its Git state.

payload paths in the two approved current Volundr roots, retaining CAS backups.
Its result is local unpublished delivery, not automatic mining or in-flight session
